# `processed/split_meta.yaml` schema

This file is generated by `notebooks/02_feature_engineering.ipynb` and consumed
by the Streamlit dashboard pages (Forecasts, Regimes). It describes the
chronological split and the feature/target columns used by saved models.

## Expected top-level keys

```yaml
target_col: target_log_return_1
feature_cols:
  - log_return
  - lag_return_1
  - lag_return_2
  - rolling_vol_7
  - rolling_vol_30
  - momentum_14
  - ...
train_end: "2019-07-19"
val_end: "2019-12-16"
test_end: "2020-05-14"
purged_train_rows: 1234
purged_val_rows: 567
```

## Key descriptions

| Key | Type | Required | Description |
|-----|------|----------|-------------|
| `target_col` | string | yes | Name of the forecast target column in the Parquet files. Must match a column in `processed/btc_features.parquet`. |
| `feature_cols` | list[string] | yes | All feature column names used by saved models. The Forecasting page checks that every listed column exists in the selected dataset. |
| `train_end` | string | yes | ISO date string marking the last training row. |
| `val_end` | string | yes | ISO date string marking the last validation row. |
| `test_end` | string | yes | ISO date string marking the last test row. |
| `purged_train_rows` | int | no | Number of rows dropped from the training partition to prevent target leakage across the train/val boundary. |
| `purged_val_rows` | int | no | Number of rows dropped from the validation partition for the same reason. |

## Notes

- The `feature_cols` list must NOT include the `target_col` itself.
- If you change the feature engineering pipeline (e.g. add new windows), regenerate
  this file by running notebook 02. The dashboard pages will fail gracefully if
  required columns are missing, showing an error message naming the gaps.
- The Forecasting page uses this file to validate that the selected Parquet
  dataset is compatible with the saved model artifact.
